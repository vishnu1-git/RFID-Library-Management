1. Legacy ILMS Protection & Protocol Isolation

Why direct SQL against legacy library databases is catastrophic, and how LibraSync isolates them.

The Industry Anti-Pattern
  • ❌ Direct Database Access: Direct raw SQL UPDATE queries against existing Koha/Sierra tables break integrity constraints and lock tables during inventory runs.
  • ❌ Cascading Catalog Corruption: Deleting or modifying physical records in production without the legacy ILMS business layer triggers orphan records.
  • ❌ Vendor Lock-In: Tightly coupling application logic to proprietary RFID C++ DLLs causes maintenance nightmares.
The LibraSync Solution
  • ✅ Zero-Touch Isolation: Legacy ILMS database is strictly read-only and foreign. LibraSync manages its own dedicated operational database (librasync).
  • ✅ Standard Protocol Boundaries: Inter-system communication occurs solely through documented standard protocols (NCIP 2.0 and 3M SIP2).
  • ✅ Device-Neutral Abstraction: Abstract RFIDReader boundary permits hot-swapping hardware vendors without modifying circulation logic.

3. Circulation State Machine & EAS Security Bit

Demonstrating Acceptance Criteria AC 03 and AC 04.

The EAS Bit Lifecycle

1. In Stacks (ARMED)

security_bit = True. Item is on shelf or returned. Passing through perimeter gates triggers the audible siren and optical CCTV snapshot.

2. Check Out (DISARMED)

security_bit = False. Staff scans member card and book EPC. Item status becomes ISSUED. Gate authorizes exit without alarm.

3. Check In (RE-ARMED)

Staff scans returned book. System reconciles overdue fines ($1.00/day), resets status to AVAILABLE, and sets security_bit = True.

AC 04 Restriction Enforcement

Reference-Only Protection

Any attempt to issue a reference-only volume is rejected with an HTTP 400 validation error before modifying database state.

Blocked Member Quarantine

Members with status BLOCKED or exceeding maximum loan limits (5 books) are rejected immediately.

One-Click Evaluation Presets

The live UI includes dedicated test preset buttons so evaluators can trigger and observe restriction rejections in real time.

5. Perimeter Gates & Offline Resilience (AC 06 & AC 09)

Loss prevention with optical surveillance and zero-downtime offline operation.

AC 06: Perimeter Loss Prevention

When an unauthorized or reference volume (security_bit = True) passes the gate portal:

  • 🚨 Audible/Visual Alarm: Flashing red perimeter warning siren.
  • 📸 Optical CCTV Capture: Mock camera adapter triggers an instant high-resolution snapshot with embedded timestamp.
  • 📝 Audit Incident Logging: Permanently writes event to gate_events table and dispatches staff alerts.

AC 09: Offline Autonomous Mode

If campus network connectivity to the backend server is lost:

  • 💾 Local Security Cache: The gate continues evaluating passages against an in-memory synchronized tag security state map.
  • ⚡ Autonomous Alarm: Armed tags continue triggering local sirens with zero server latency.
  • 🔄 Persistent Outbox Queue: Offline events are buffered and automatically replayed to the server upon reconnection.
