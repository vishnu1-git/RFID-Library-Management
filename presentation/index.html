Integrity & Boundaries

Zero-Corruption Legacy ILMS Protection

How LibraSync satisfies Section 1 and Section 3 of the AISYS SOP.

The Industry Anti-Pattern (What Destroys ILMS Data)
  • Direct Database Access: Direct SQL UPDATE or DELETE queries against existing Koha/Sierra tables bypass internal triggers and cause catastrophic table locks.
  • Foreign Key Corruption: Directly inserting or pruning records in external ILMS tables corrupts cascade relationships and circulation histories.
  • Vendor SDK Hardcoding: Writing business logic against vendor-specific C++ DLLs locks the library into proprietary hardware.
The LibraSync Solution (Strict Architectural Defense)
  • Independent Operational Database: LibraSync operates exclusively on its own database (librasync). Zero queries ever run against external ILMS tables.
  • Standard Protocol Boundaries: All inter-system synchronization occurs through standardized protocol adapters (NCIP 2.0 and 3M SIP2).
  • Device-Neutral Normalization: Abstract hardware adapter layer converts proprietary signals into normalized RFIDEvent dictionaries before hitting domain logic.
Boundary Code: backend/app/integrations/ilms/base.py | ncip_adapter.py | sip2_adapter.py

Circulation Engine

EAS Security State Machine & Restriction Rules

Demonstrating compliance with Priority Acceptance Criteria AC 03 and AC 04.

The 3-Phase EAS Security Bit Lifecycle

1. In Stacks / Check-In (ARMED)

security_bit = True. Item is on shelf. Unauthorized passage through 3D exit gate triggers siren alarm and CCTV capture.

2. Check-Out / Issued (DISARMED)

security_bit = False. Staff scans member badge and item EPC. Item status becomes ISSUED. Gate permits exit.

3. Check-In / Returned (RE-ARMED)

Returned item scanned. System calculates overdue fine ($2.00/day), updates status to AVAILABLE, and sets security_bit = True.

AC 04 Circulation Restrictions Engine

1. Reference-Only Volume Rejection

Books flagged with is_reference_only = True are blocked from loan. Checkout is rejected immediately with an HTTP 400 error.

2. Blocked Patron Rejection

Patrons with status BLOCKED or outstanding overdue fines exceeding $100 are rejected immediately.

3. Live One-Click Demonstration Presets

The live UI includes dedicated evaluation buttons allowing evaluators to verify restriction rejections instantly.

Perimeter Security

3D Gate Loss Prevention & Offline Autonomy

Perimeter theft protection with optical CCTV capture and zero-downtime offline caching.

AC 06: Perimeter Loss Prevention

When an armed tag (security_bit = True) passes through portal GATE-PORTAL-01:

  • Audible & Visual Alarm: Immediate perimeter siren triggers.
  • Optical CCTV Snapshot: Camera adapter captures evidentiary frame with timestamp and portal coordinates.
  • Audit Incident Logging: Writes event to gate_events and queues staff notification.

AC 09: Offline Autonomous Gate Resilience

If campus network connectivity to the backend server drops:

  • Local Security State Cache: Gate evaluates passages against an in-memory synchronized tag security map.
  • Autonomous Siren: Armed tags trigger local sirens with zero server dependency.
  • Persistent Outbox Queue: Passage events buffer locally and replay automatically upon server reconnection.
